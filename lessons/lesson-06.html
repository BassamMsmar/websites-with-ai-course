    رفع المواقع (1): Git و GitHub

    وداعًا «نسخة نهائية 2» لقطات ترجع إليها متى شئت مشاريعك الأربعة على GitHub

    مشكلة «نسخة نهائية 2»

    افتح مجلد أي مشروع قديم وستجد: final، final-2، final-REAL، final-before-change. كل مجلد نسخة كاملة، ولا أحد يذكر الفرق بينها، وأي تعديل خاطئ يعني البحث في المجلدات عن آخر نسخة كانت تعمل.

    مع الذكاء الاصطناعي تتضاعف المشكلة: تطلب تعديلًا صغيرًا فيغيّر عشرة ملفات دفعة واحدة، ويكسر شيئًا كان يعمل، ولا تعرف ماذا غيّر بالضبط. Git هو الحل، وهو أهم أداة في هذه المادة بعد المتصفح.

    Git: كاميرا تصوّر مجلدك

    تخيّل كاميرا تلتقط صورة لمجلد المشروع كاملًا كلما طلبت. كل صورة اسمها لقطة (Commit)، ولها رسالة تصف ما تغيّر. الصور تُحفظ بالترتيب في سجل (History)، وتستطيع في أي لحظة أن تعود إلى أي صورة قديمة. المجلد نفسه اسمه مستودع (Repository).

    ما يميّز Git عن نسخ المجلدات: لا تكرار للملفات، ورسالة مع كل لقطة، ومقارنة دقيقة تخبرك أي سطر تغيّر في أي ملف.

    ما تريدهالأمربلغة بسيطة
    ابدأ التصوير في هذا المجلدgit initيحوّل المجلد إلى مستودع (مرة واحدة فقط)
    ما الذي تغيّر منذ آخر لقطة؟git statusقائمة الملفات المعدّلة والجديدة
    جهّز كل التغييرات للقطةgit add .النقطة تعني «كل شيء»
    التقط الصورة برسالةgit commit -m "أضفت صفحة التواصل"الرسالة تصف ما فعلت، للمستقبل
    اعرض السجلgit log --onelineسطر لكل لقطة: رقم قصير + الرسالة
    ألغِ التعديلات التي لم أصوّرها بعدgit restore .يعيد الملفات إلى آخر لقطة
    أعد ملفات لقطة قديمةgit checkout a1b2c3 -- .يجلب ملفات اللقطة رقم a1b2c3، ثم تصوّر لقطة جديدة

    سبعة أوامر تكفي المادة كلها. وإن كانت الأوامر تزعجك فبرنامج GitHub Desktop يفعل الشيء نفسه بأزرار: Commit، History، Push. الفكرة واحدة.

    القاعدة الذهبية مع الذكاء الاصطناعي

    لقطة قبل كل طلب. قبل أن تطلب من الذكاء الاصطناعي أي تعديل، صوّر لقطة. إن أعجبك التعديل، صوّر لقطة أخرى. إن كسر شيئًا، git restore . ويعود كل شيء كما كان في ثانية. بلا Git، الرجوع يعني إعادة البناء.

    الرسالة الجيدة

    الرسالة تُقرأ بعد شهر حين تنسى ما فعلت. اكتب ماذا ولماذا بجملة قصيرة:

    • سيئة: تعديلات، update، fix.
    • جيدة: أضفت زر واتساب ثابتًا للجوال، أصلحت مسارات الصور بعد نقلها إلى assets.

    GitHub: نسخة في السحابة، وموقع مجاني

    Git يعمل على جهازك. GitHub موقع يحفظ نسخة من مستودعك على الإنترنت، فيصبح لديك: نسخة احتياطية، ومكان يراه الآخرون (المدرّب، صاحب عمل)، وموقع منشور مجانًا.

    المصطلحمعناه
    Repository على GitHubنسخة مستودعك في السحابة. لكل مشروع مستودع.
    Pushارفع لقطاتي الجديدة من جهازي إلى GitHub.
    Pullأنزل ما على GitHub إلى جهازي (إن عدّلت من جهاز آخر).
    README.mdملف نصي يظهر في صفحة المستودع: ما المشروع، كيف يُفتح، رابط الموقع الحي. أول ما يقرؤه الزائر.
    Pull Requestاقتراح تعديل للمراجعة قبل دمجه. تستخدمه الفرق، وستراه كثيرًا، لكنك في مشروعك الفردي لا تحتاجه الآن.
    GitHub Pagesخدمة تنشر مستودعك كموقع على رابط اسمك.github.io/اسم-المستودع. مجانية.

    الدرجة الثالثة من سلّم النشر

    ما الفرق عن Netlify Drop؟ في Netlify Drop تسحب المجلد كل مرة وتحصل على رابط جديد. في GitHub Pages: كل git push يحدّث الموقع تلقائيًا على الرابط نفسه، ومع سجل كامل لكل نسخة. هذا هو الفرق بين «رفع ملفات» و«نشر مشروع».

    تفعيله ثلاث نقرات: صفحة المستودع ← Settings ← Pages ← اختر Branch: main ← Save. بعد دقيقة يظهر الرابط.

    للمتقدمين

    هذا الموقع الذي تقرأ منه مستودع Git أيضًا. افتح git log --oneline في مجلده وسترى كيف بُني درسًا درسًا. وجرّب git diff بعد أي تعديل: يعرض بالضبط الأسطر التي تغيّرت، بالأحمر ما حُذف وبالأخضر ما أُضيف. هذه أفضل طريقة لمراجعة ما فعله الذكاء الاصطناعي قبل أن تقبله.

    مسرد الدرس

    Git
    أداة تحفظ لقطات من مجلد المشروع وتتيح الرجوع إلى أي لقطة.
    مستودع Repository / Repo
    مجلد المشروع بعد تفعيل Git فيه، أو نسخته على GitHub.
    لقطة Commit
    صورة محفوظة للمجلد كاملًا مع رسالة تصف التغيير.
    سجل History / Log
    قائمة اللقطات بالترتيب الزمني.
    استرجاع Restore / Checkout
    إعادة الملفات إلى حالة لقطة سابقة.
    GitHub
    موقع يستضيف مستودعات Git في السحابة ويوفر GitHub Pages.
    رفع Push
    إرسال اللقطات الجديدة من جهازك إلى GitHub.
    README.md
    ملف تعريف المشروع الذي يظهر في صفحة المستودع.
    طلب دمج Pull Request
    اقتراح تعديل للمراجعة قبل دمجه في المشروع. للفرق.
    GitHub Pages
    نشر المستودع كموقع مجاني يتحدث مع كل push.

    مخرج اليوم: كسرت موقعك عمدًا واسترجعته بـ Git، ثم مشاريعك الأربعة على GitHub بروابط GitHub Pages حية.

    الجزء الأول: التجهيز (15 دقيقة)

    1. ثبّت Git.

      من git-scm.com. اترك الخيارات الافتراضية. للتأكد افتح الطرفية (Terminal) واكتب git --version.

    2. أنشئ حسابًا على GitHub باسم مهني (اسمك الحقيقي أو قريب منه). هذا الحساب سيظهر في سيرتك.
    3. عرّف Git بنفسك مرة واحدة: 
      git config --global user.name "اسمك"
git config --global user.email "بريدك@example.com"

    الجزء الثاني: اكسر واسترجع (25 دقيقة)

    نستخدم مشروع الدرس 2 (my-card). افتح الطرفية داخل مجلده (في VS Code: Terminal ← New Terminal).

    1. ابدأ التصوير وصوّر أول لقطة. 
      git init
git add .
git commit -m "النسخة الأولى من البطاقة الرقمية"
git log --oneline

      سترى سطرًا واحدًا برقم قصير ورسالتك.

    2. التخريب الأول (بلا لقطة).

      افتح style.css، حدد كل محتواه واحذفه، احفظ. افتح الموقع في المتصفح: بلا تنسيق. الآن:

      git status
git restore .

      حدّث المتصفح. عاد كل شيء. هذا ما ستفعله كل مرة يكسر الذكاء الاصطناعي شيئًا.

    3. التخريب الثاني (بلقطة).

      غيّر لون العنوان في CSS إلى أصفر فاقع واحفظ، ثم صوّر لقطة: git add . ثم git commit -m "جربت الأصفر". الآن الخراب محفوظ في السجل. للرجوع:

      git log --oneline
git checkout [رقم اللقطة الأولى] -- .
git commit -m "رجعت إلى اللون الأصلي"

      لاحظ: لم نحذف لقطة «الأصفر» من السجل، بل أضفنا لقطة جديدة تعيد الملفات. السجل لا يُمحى، وهذا مقصود.

    4. طبّق القاعدة الذهبية.

      اطلب من الذكاء الاصطناعي تعديلًا حقيقيًا على البطاقة (مثل إضافة قسم مهارات). قبل لصق النتيجة: لقطة. بعد التأكد أنها تعمل: لقطة برسالة تصف الإضافة.

    الجزء الثالث: على GitHub وعلى الهواء (50 دقيقة)

    1. أنشئ مستودعًا على GitHub.

      الزر الأخضر New. الاسم: my-card. اتركه Public. لا تضف README من هنا (لديك ملفات). Create repository.

    2. اربط وارفع.

      GitHub سيعرض لك الأوامر. هي ثلاثة:

      git remote add origin https://github.com/اسمك/my-card.git
git branch -M main
git push -u origin main

      سيطلب تسجيل الدخول أول مرة. بعدها حدّث صفحة GitHub: ملفاتك هناك.

    3. أضف README.md.

      ملف نصي في جذر المشروع بثلاثة أسطر: اسم المشروع، جملة عنه، ورابط الموقع الحي (ستضيفه بعد الخطوة التالية). ثم لقطة و git push.

    4. فعّل GitHub Pages.

      Settings ← Pages ← Branch: main ← Save. انتظر دقيقة وحدّث الصفحة. الرابط: https://اسمك.github.io/my-card/. افتحه على جوالك. أنت على الدرجة الثالثة.

    5. كرّر للمشاريع الثلاثة الأخرى (النشاط التجاري، المعرض، العرض التقديمي). لكل مشروع: git init، لقطة، مستودع جديد على GitHub، push، Pages. المرة الثانية تأخذ 5 دقائق.
    6. جرّب التحديث التلقائي.

      عدّل شيئًا صغيرًا في أي مشروع، لقطة، git push. انتظر دقيقة وحدّث الرابط: التعديل ظهر بلا سحب وإفلات.

    7. أرسل للمدرّب رابط حسابك على GitHub. فيه المستودعات الأربعة وروابطها الحية.
    إذا تعثّرت
    • الأوامر ترعبني: ثبّت GitHub Desktop. Add local repository ← اختر المجلد ← Commit ← Publish repository. الأزرار نفسها الأوامر.
    • git: command not found: Git لم يُثبّت أو الطرفية لم تُعد فتحها بعد التثبيت. أغلق VS Code وافتحه.
    • Pages يعطي 404: إما لم تمر دقيقة بعد، أو index.html ليس في جذر المستودع، أو الاسم Index.html. نفس درس المسارات.
    • push يطلب كلمة مرور ويرفضها: GitHub لا يقبل كلمة المرور في الطرفية. سجّل الدخول من النافذة التي تظهر، أو استخدم GitHub Desktop.
    • الموقع يعمل على جهازي ومكسور على Pages: مسار يبدأ بـ / (مطلق). اجعله نسبيًا. راجع الدرس 4.
    للمتقدمين
    • أنشئ فرعًا (branch) باسم experiment، جرّب فيه تعديلًا جريئًا، ثم ادمجه أو احذفه: git switch -c experiment.
    • افتح Pull Request من الفرع إلى main على GitHub واقرأ كيف يعرض الفرق. هكذا تعمل الفرق البرمجية.
    • أضف ملف .gitignore يتجاهل الملفات المؤقتة مثل .DS_Store وThumbs.db.

    تلخيص المفاهيم

    • Git كاميرا تصوّر لقطات (commits) من مجلد المشروع، لكل لقطة رسالة، وتستطيع الرجوع إلى أيها.
    • سبعة أوامر: init، status، add .، commit -m، log --oneline، restore .، checkout [رقم] -- .
    • القاعدة الذهبية: لقطة قبل كل طلب من الذكاء الاصطناعي، ولقطة بعد التأكد.
    • restore . يلغي ما لم يُصوَّر بعد. checkout [رقم] -- . يجلب ملفات لقطة قديمة ثم تصوّر لقطة جديدة. السجل لا يُمحى.
    • GitHub نسخة سحابية: push يرفع، README يعرّف، Pull Request للفرق، وGitHub Pages ينشر مجانًا.
    • الدرجة الثالثة: كل push يحدّث الموقع تلقائيًا على الرابط نفسه، مع سجل كامل.

    الاختبار

    عشرة أسئلة عن أوامر Git وسيناريوهات الاسترجاع. اختر إجابة لترى التصحيح والشرح فورًا.
